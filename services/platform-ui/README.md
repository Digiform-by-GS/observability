# platform-ui

The platform's front door: every service it has heard from, who owns it, whether
it is actually sending all three signals, and the Grafana panels for it embedded
inline.

```
docker compose -f docker-compose.yml -f docker-compose.platform.yml \
               -f docker-compose.ui.yml up -d --build platform-ui
# then http://<host>:8200
```

## What it is for

Grafana already has a Service Inventory dashboard, and this does not replace it.
What it does is put the one question Grafana answers *worst* on the front page:

> Is this service sending logs at all?

Every RED panel on the platform is derived from spans by Tempo's metrics
generator. A service that emits traces and no logs therefore renders as
completely healthy on all of them — the absence is invisible precisely where
someone would go looking. Showing traces and logs as two columns side by side,
per service, is the reason this page exists.

The second thing it does is remove a navigation step. Finding a service's
latency previously meant opening Grafana, picking the right dashboard, then
setting three template variables. Here, clicking a row does it.

## How it gets its data

Mimir and Loki are queried **directly**, not through Grafana's datasource proxy.
Grafana's `/api/ds/query` needs an authenticated session and speaks an envelope
that changes between versions; the backends' own APIs are stable and public.

The cost of that choice is the tenant header. Mimir takes one `X-Scope-OrgID`
per query and accepts a pipe-separated list to read across tenants — the same
trick Grafana's provisioned datasource uses. `MIMIR_TENANTS` must therefore stay
in step with `infra/tenants.yaml`, or **a new team's services are simply missing
from the catalogue** with nothing logged to say so.

The PromQL is copied from the Service Inventory dashboard rather than reinvented,
because two definitions of "what counts as a service" is how a UI and its
dashboards start quietly disagreeing.

## Embedding

Panels are embedded with Grafana's `/d-solo/<uid>/<slug>?panelId=N` endpoint,
which renders a single panel with no chrome. Two things had to be true first,
and neither announces itself when it is false:

1. **`allow_embedding = true`** in `infra/grafana/grafana.ini`. Grafana defaults
   it to false and sends `X-Frame-Options: deny`, so every iframe renders blank
   with nothing logged anywhere.
2. **Panels need stable ids.** Provisioned dashboards without explicit ids come
   back from Grafana's API as `id: null`, so there is nothing to point `panelId`
   at. `scripts/gen-dashboards.py` now assigns them at the one function every
   dashboard passes through.

`GRAFANA_URL` is the address a **browser** must reach, because it ends up in an
`<iframe src>`. `http://grafana:3000` works from inside the network and shows
every user a blank panel.

## Configuration

| Variable | Default | Notes |
|---|---|---|
| `GRAFANA_URL` | *required* | **Browser-facing.** Used in iframe URLs. |
| `MIMIR_URL` | `http://mimir:9009` | Server-side; container DNS is right here. |
| `LOKI_URL` | `http://loki:3100` | Empty disables the log column rather than failing. |
| `MIMIR_TENANTS` | `platform\|unattributed\|gudangsolusi\|anonymous` | Keep in step with `infra/tenants.yaml`. |
| `TEAMS_FILE` | `/etc/platform/teams.json` | Generated by `gen-tenants.py`. |
| `PORT` | `8200` | |
| `REQUEST_TIMEOUT_MS` | `10000` | Per backend query. |

## Access

Read-only and unauthenticated, matching Grafana's anonymous Viewer on this
deployment — a front door harder to open than the dashboards behind it would
just be bypassed. It holds no credential and has no write path.

It is **not** a PromQL proxy. The queries are fixed and only the time window is
a parameter, chosen from an allow-list rather than clamped, because that value
is interpolated into PromQL.

## Development

```
npm install
npm test        # typecheck, build, then node --test
npm run build && GRAFANA_URL=http://localhost:3000 MIMIR_URL=http://localhost:9009 npm start
```

`npm run build` copies `src/public` into `dist/` — `tsc` only emits `.js`, so
without that step the page 404s outside Docker.
