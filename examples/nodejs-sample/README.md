# @digiform/nodejs-sample

Express demo that exercises [`@digiform/observability`](../../packages/observability/) end-to-end. Hits send OTLP to the local Collector; data lands in Loki / Tempo / Mimir and renders in Grafana with full correlation.

## Prerequisites

The Step 1 stack must be running:

```bash
# from repo root
docker compose up -d
docker compose ps                   # all five services healthy
# if you hit "permission denied on /var/run/docker.sock" on WSL,
# prefix with sudo or add yourself to the docker group.
```

## Run the app

```bash
# from repo root
npm install                                       # picks up this workspace
npm run -w @digiform/nodejs-sample start          # listens on PORT (default 8080)
```

Run on a non-default port: `PORT=9090 npm run -w @digiform/nodejs-sample start`.

> **WSL2 + `/mnt/c|d|...` cold-start caveat:** if the repo lives on a Windows drive mounted into WSL (`/mnt/d/...`), the first boot can take **2–3 minutes** because Node has to resolve hundreds of `@opentelemetry/*` files across the slow 9P bridge. Subsequent boots are fast (warm OS file cache). Move the repo to native WSL storage (`~/observability`) to skip this entirely.

## Endpoints

| Route | What it demonstrates |
|---|---|
| `GET /healthy` | Baseline trace + log + metric tick. |
| `GET /slow` | Non-trivial span duration (200–500ms random). Surfaces on the p95 panel. |
| `GET /error` | Throws. Drives the error-rate panel; produces an error log line with a matching trace_id. |
| `GET /work` | Custom span wraps a self-call to `/healthy`. Demonstrates W3C traceparent propagation and custom instrumentation (`getTracer`, `getMeter`). |

## Generate traffic

```bash
for i in $(seq 1 30); do
  curl -s http://localhost:8080/healthy > /dev/null
  curl -s http://localhost:8080/slow    > /dev/null
  curl -s http://localhost:8080/error   > /dev/null
  curl -s http://localhost:8080/work    > /dev/null
  sleep 1
done
```

## What to look for in Grafana ([http://localhost:3000](http://localhost:3000))

### 1. The dashboard
**Dashboards → Observability → Observability Overview** — within ~30s of traffic the four panels populate:
- Request rate, error rate, p95 latency (from Tempo's span-metrics generator → Mimir).
- A log stream of `{service_name="nodejs-sample"}`.

### 2. Logs → trace
**Explore → Loki**, query `{service_name="nodejs-sample"}`. Each line carries `trace_id` and `span_id` (added by the wrapper's pino mixin). Click any line → the "View Trace" link (from the Loki datasource's `derivedFields` config) jumps you straight to that trace in Tempo.

### 3. Trace → log (the other direction)
Inside any trace in Tempo, click a span's "Logs for this span" — the Tempo datasource's `tracesToLogsV2` config queries Loki for matching `trace_id` and surfaces every log line for that request.

### 4. A `/work` trace's shape
Search Tempo for `{ resource.service.name = "nodejs-sample" && name = "GET /work" }`. Expand a result. You should see:
- **Express server span** for `/work` (parent, auto-instrumented)
- **`downstream-fetch`** (custom span, see [src/routes.ts](src/routes.ts))
- **HTTP client span** for the self-call (auto-instrumented)
- **Express server span** for `/healthy` (the same request hits the server again, parented via `traceparent` header)

### 5. Custom metric
**Explore → prometheus**, query `app_work_invocations_total`. Should increment per `/work` request. Also: `traces_spanmetrics_calls_total{service_name="nodejs-sample"}` for the span-metrics auto-generated by Tempo.

### 6. Service graph
**Explore → Tempo → Service Graph** — `nodejs-sample` appears as a node calling itself (via the `/work` → `/healthy` chain). Drawn from the service-graph metrics Tempo's generator pushes to Mimir.

## Troubleshooting

| Symptom | Where to look |
|---|---|
| Nothing anywhere in Grafana | `curl -i http://localhost:4318/v1/traces -d '{}' -H 'Content-Type: application/json'` — should return 200. If it fails, the Collector isn't reachable. `docker compose logs otel-collector`. |
| Traces present, logs missing | The pino transport runs in a worker thread without the parent env. Check that the wrapper passes `resourceAttributes` into transport options — should be wired in `packages/observability/src/logging.ts`. |
| Logs present, no "View Trace" link | Open a log line's details — `trace_id` should be present. If it's missing, the active span isn't being captured by the pino mixin (likely an SDK init-order issue — confirm `start` script preloads `@digiform/observability/preload`). |
| Express requests show but no spans for them | SDK init ran AFTER express was loaded. Verify `--import @digiform/observability/preload` is in the `start` script (it must come after `--import tsx` but before any application import). |

## Stopping

`Ctrl+C` flushes telemetry and closes the HTTP server gracefully.
